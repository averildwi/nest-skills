# Usage

## 1. Install

Run from the root of a NestJS project (a `package.json` that lists `@nestjs/core`).

```bash
npx @averildwi/nest-skills                  # asks which agent
npx @averildwi/nest-skills --agent claude   # no question
npx @averildwi/nest-skills --agent both --yes
```

Without a terminal (CI, scripts) or with `--yes`, `--agent` is required on the first install.
Later runs read the agent and folder from `.nest-skills.json`.

### Which agent?

| Choose | When |
|---|---|
| `opencode` | Only OpenCode is used. Skills go to `.opencode/skills`. |
| `claude` | Only Claude Code is used. Skills go to `.claude/skills`, plus a `CLAUDE.md` that imports `AGENTS.md`. |
| `both` | The team uses both. One copy in `.claude/skills`, which OpenCode also reads. Installing into two folders would make OpenCode see every skill twice, and skill names must be unique. |

Sources: OpenCode [skills](https://opencode.ai/docs/skills/) and [rules](https://opencode.ai/docs/rules/),
Claude Code [skills](https://code.claude.com/docs/en/skills) and [memory](https://code.claude.com/docs/en/memory).
Claude Code reads `AGENTS.md` by itself only when there is no `CLAUDE.md` and only on newer
versions. The `@AGENTS.md` import in `CLAUDE.md` works in every case.

### Custom folder

```bash
npx @averildwi/nest-skills --agent opencode --dir .agents/skills
```

`AGENTS.md` is rendered with the folder you choose, so the agent is told the real path.
The folder must be relative and inside the project.

## 2. Commit

```bash
git switch -c chore/agent-skills
git add AGENTS.md .opencode/skills .nest-skills.json      # adjust to the printed list
git commit -m "chore: add agent skills"
```

Commit generated files on their own, before you edit anything (`git-workflow` rule 6).

## 3. Update to a newer version

```bash
npx @averildwi/nest-skills@latest update --dry-run   # see what would change
npx @averildwi/nest-skills@latest update
```

| File state | `install` | `update` | with `--force` |
|---|---|---|---|
| missing | created | created | created |
| same as bundled | skipped | skipped | skipped |
| written by us, unedited, older | reported ("run update") | **refreshed** | refreshed |
| written by us, **edited by you** | kept | kept | replaced, your copy in `.bak` |
| **not written by us**: a skill file | kept | kept | replaced, your copy in `.bak` |
| **not written by us**: `AGENTS.md` / `CLAUDE.md` | kept | kept | **kept** |

"Written by us" means the path and its hash are in `.nest-skills.json`. If you delete that
file, every installed file counts as yours and will not be updated.

## 4. Switching agent

```bash
npx @averildwi/nest-skills --agent claude
```

`AGENTS.md` (if unedited) is rewritten to point at the new folder and `CLAUDE.md` is added.
The old skills folder is **not deleted**; the CLI prints the `git rm -r` command to run.

## 5. When you already have AGENTS.md or CLAUDE.md

- Own `AGENTS.md`: kept. The index is written to `AGENTS.nest-skills.md`. Add a line to your
  `AGENTS.md` such as `Read AGENTS.nest-skills.md before writing NestJS code and follow it.`
- Own `CLAUDE.md`: kept. Add `@AGENTS.md` (or `@AGENTS.nest-skills.md`) as its first line.
  If it already has that line, nothing is reported.

## 6. Existing scaffold code that differs from the skills

The skills describe the target standard. Code generated by older `nest-common`/`nest-prisma`
versions may differ (optional `page?` in `PaginationDto`, `string[]` roles, `any` in
interceptors, CORS `'*'`, no Jest `moduleNameMapper`). The section
"When the existing code differs from these skills" in `AGENTS.md` tells the agent to adapt
at the call site, not rewrite shared code silently, and to propose a separate commit.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | done, or nothing to do |
| 1 | not a NestJS project, invalid `package.json` / `.nest-skills.json`, write error |
| 2 | bad arguments, `--agent` missing in non-interactive mode, `update` without an install |
| 130 | cancelled |
